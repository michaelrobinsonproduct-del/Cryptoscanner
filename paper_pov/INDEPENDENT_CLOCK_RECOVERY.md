# OWNER D — independently clocked PAPER recovery proposal (audit-only)

**Root cause boundary:** GitHub's \`schedule\` events may be delayed or dropped. No GitHub Actions YAML, extra cron, runner retry, or \`workflow_run\` fanout guarantees :09/:39 creation. The observed six-hour deficit (issue #34) is upstream of writer queueing. Do not describe a \`workflow_dispatch\` recovery as a native schedule.

**Existing usable alternative (already on main; do not clone a writer):**
1. An independently clocked, owner-authenticated service can post the exact issue #34 command \`/paper-cadence-heartbeat\` at the desired cadence. GitHub's existing \`paper-cadence-wake.yml\` consumes the \`issue_comment\` event. Alternatively, \`/paper-recovery-heartbeat\` wakes the existing \`paper-recovery.yml\` via \`paper-external-heartbeat.yml\`. These are different commands and must not both be sent for one slot.
2. Existing controller logic validates owner identity, event age, main SHA, GitHub writer-run history, immutable ledger, and prior attempt markers. The cadence and recovery controllers share \`public-paper-recovery-controller\` with \`cancel-in-progress: false\`.
3. A successful controller decision may request **only** \`paper-pipeline.yml\` on \`main\`; its existing \`public-paper-proof-ledger-single-writer\` mutex is noncancelling. A dispatch HTTP response proves neither creation nor scan success. Actual ledger generation, results artifacts, quote age, and end-user delivery need separate verification.
4. \`independent_wake_rehearsal.py\` composes the actual existing owner authorization and controller decision, verifies source contracts from the exact checkout, and **never** invokes a dispatch API or writes a ledger. Its 18 failure-injection tests cover spoofed/stale events, changed writer or controller mutexes, foreign source, duplicate suppression, extra writer, and false recovery claims.

**Production blockers requiring owner approval and independent audit:** an independent external 30-minute heartbeat source is not yet demonstrated; GitHub-only scheduled controllers share the unreliable native scheduler. The current GitHub API \`workflow_dispatch\` has no synchronous returned writer run ID; timing correlation is not causal provenance. A noncancelling concurrency group serializes writers but does **not** guarantee durable UTC-slot idempotency across sequential duplicate requests. B must add an immutable UTC slot claim/compare-and-swap gate shared by native, owner, and recovery, with a readback receipt. C must inventory external writers and independently audit the owner-trigger chain. V must prove Kraken exchange-event age <=600s and user-facing results receipt.

**Owner authorization acceptance:** (a) exact-head CI and offline adversarial suite green; (b) independent audit certification; (c) explicit authorization for one nonproduction owner-comment rehearsal; (d) authenticated GitHub \`issue_comment\` run ID, exact source SHA and controller decision artifact; (e) if and only if explicitly approved for live recovery, one linked writer run, one slot claim, one ledger increment and one results-delivery receipt; (f) fail closed on duplicate, delayed, stale, foreign actor, ambiguous writer, source drift, or missing external clock. Never count recovery toward native schedule punctuality.

**Current limitation:** This branch does not install an external clock, post an owner comment, dispatch a writer, change production YAML, or establish live end-to-end recovery. Branch-only \`issue_comment\` workflows cannot be exercised as a default-branch production event without a main change. A PR \`pull_request\` CI rehearsal can validate code and source contracts but not authenticate the real owner event or its delivery.
